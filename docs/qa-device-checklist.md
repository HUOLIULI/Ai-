# 真机验证清单（QA Device Checklist）

本清单汇总需要在 **Android 真机**上验收的功能，重点是本轮新增的 AI 增强套件与原生 bitmap LUT 后端。Web 端逻辑已被 261 个单元测试覆盖，但原生渲染、模型往返观感、真机延迟与内存只能实机验证。

> **前提**：AI 增强与原生滤镜模块（`modules/image-filter`）**不支持 Expo Go**。验证前必须用本地 Android SDK 重新构建开发包或 APK，把 `ImageFilter` 模块链进应用：
>
> ```bash
> cd Drama && npx expo run:android
> ```

---

## 0. 构建与模块链接

- [ ] `npx expo run:android` 构建成功，应用能安装并启动。
- [ ] 无 `requireOptionalNativeModule('ImageFilter')` 为 null 的报错（原生模块已链接）。
- [ ] 无 `requireOptionalNativeModule('CameraTuning')` 为 null 的报错。
- [ ] 启动时无红屏 / 原生崩溃；Expo Modules 自动链接日志里能看到 `image-filter` 与 `camera-tuning`。

---

## 1. 内置风格滤镜（原生 bitmap 后端）

验证原生 LUT 后端真的改写了像素（此前原生端是占位、返回原图）。

- [ ] 在「清透 / 奶杏 / 薄荷 / 胶片 / 黑白 / 港风 / 日系 / 复古」八套风格下各拍一张，**成片色调与取景风格一致**（色偏、对比、颗粒可见变化），而非原图。
- [ ] 切换风格后连拍，成片风格随切换而变，不串味。
- [ ] 八套风格的色偏方向正确：胶片偏暖、薄荷偏冷、奶杏偏柔和、清透接近中性提亮、黑白去饱和、港风青橙、日系粉调提亮、复古褪色暖旧。

## 2. AI 自动调色

- [ ] 开启「AI 调色」开关，拍一张，成片相比仅套风格滤镜有明显调色变化。
- [ ] 关闭「AI 调色」，成片回落到仅风格滤镜，无残留。
- [ ] 断网或模型失败时拍摄，**成片仍是风格滤镜结果**（fail-open，不阻塞、不报错卡死）。
- [ ] 模型往返延迟可接受（调色走一次模型请求；同时开调色 + 美颜为两次，注意叠加延迟）。

## 3. AI 美颜

- [ ] 开启「AI 美颜」，拍人像，肤色更柔和/提亮/暖化（观感级，非空间模糊）。
- [ ] 美颜套在调色之上，两者同时开时效果叠加且不冲突。
- [ ] 关闭或模型失败时，保留未美颜照片（fail-open）。
- [ ] 确认**空间效果边界**：美颜是逐像素 LUT 观感，真·皮肤模糊/眼部提亮不在本轮范围（需 GPU/原生后端）。

## 4. AI 智能场景识别

- [ ] 开启「AI 场景」，对准人像/风景/夜景等场景，采样后自动切到匹配的模式与风格（置信度 ≥ 0.6 才切）。
- [ ] 置信度低或识别失败时，**保留用户手动选择的模式/风格**，不乱切。
- [ ] 三个非人像非夜景场景（美食/逆光/微距）回落到「风景」模式、靠风格区分——确认观感合理。

## 5. 自然语言修图

- [ ] 拍照后进入回顾页，在「一句话修图」输入框输入指令（如「把天空调蓝一点」），点「应用」。
- [ ] 预览图更新为修图结果；指令未提的参数保持中性。
- [ ] **Android 关键路径**：确认模型收到的是 base64 data URL（原生滤镜输出是 `file://`，经 `toDataUrl` 转换），修图真的生效而非失败。
- [ ] 模型失败 / 未配置 AI 时，显示错误提示、**保留原图**（绝不毁原图）。
- [ ] 未输入指令时「应用」按钮隐藏。

## 6. AI 照片评分

- [ ] 回顾页点「AI 照片评分」，出现五维分数条（构图/光线/色彩/锐度/美学）+ 总分 + 一句总评 + 改进建议。
- [ ] 五维分数各落在 0–100，总分约为五维均值。
- [ ] 换一张照片后评分重置，需重新点按；未点过不重复请求。
- [ ] 模型失败/未配置 AI 时，显示提示、**保留原图**（评分是展示型，不影响选片与保存）。

## 7. 三分法构图

- [ ] 取景框叠加三分网格线，构图提示吸附到三分交点。
- [ ] 网格线与提示不溢出取景框、不遮挡控制按钮。

## 8. 既有功能回归（确认未被本轮改动破坏）

- [ ] 拍摄 → 回顾 → 保存到相册 → 自动继续拍摄，全链路通。
- [ ] 相机实时参数微调（白平衡/对比度/变焦）仍按设备能力工作。
- [ ] 成片质量守护（模糊/曝光/闭眼提示重拍）仍工作。
- [ ] Web 端（`npm run web`）八套风格滤镜 + AI 增强（canvas 后端）正常。

## 性能与资源（重点观测）

- [ ] **解码内存**：12MP 照片在原生 `ImageFilter` 解码为 ARGB_8888 Bitmap 的内存峰值（约 48MB），低端机上观察是否 OOM。
- [ ] **连续滤镜耗时**：风格 → 调色 → 美颜会在原生端连续做多次「解码 + 逐像素 + 编码 JPEG」，观测总耗时是否可接受、有无明显卡顿。
- [ ] **重复 JPEG 压缩**：每步滤镜都重编码 JPEG（quality 95），多步叠加有轻微生成损耗——确认观感可接受。
- [ ] **快门 base64**：调色/美颜复用快门照片 base64（不二次采样），确认 `takePictureAsync({ base64: true })` 对快门体积/速度的影响。

## 已知限制（非缺陷，验收时不要误判为 bug）

- 美颜是 LUT 观感级，非真空间模糊。
- 调色/美颜/NL 修图的**像素效果**在 Android 与 web 生效；iOS 暂走 canvas（fail-open，返回原图），原生 iOS bitmap 后端待建。
- HDR / 夜景降噪 / 超分辨率 / AI 消除 / 人像虚化（抠图）/ Live Photo 需原生计算摄影 + 生成式/分割模型，本轮未做、未用 LUT 假装。
- 阈值/观感（场景置信度 0.6、调色/美颜强度、模型往返延迟）需真机标定后可能微调。
